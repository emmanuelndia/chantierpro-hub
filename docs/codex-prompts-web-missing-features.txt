# Prompts Codex - Fonctionnalités Web Manquantes ChantierPro

Contexte commun :
- Application : ChantierPro, gestion BTP.
- Surface cible : version web desktop/tablette.
- La version web doit reprendre les fonctionnalités de gestion, consultation et pilotage de la version mobile.
- Exclure les fonctionnalités terrain propres au mobile :
  - pointage GPS;
  - prise de photo caméra;
  - mode offline PWA;
  - synchronisation offline.
- Garder les règles métier actuelles :
  - ressources terrain globales et tournantes;
  - un utilisateur terrain peut être assigné sur plusieurs chantiers le même jour;
  - `PROJECT_MANAGER` gère ses projets/chantiers;
  - `GENERAL_SUPERVISOR` planifie uniquement les sites qui lui sont confiés;
  - `DIRECTION`/`ADMIN` ont une vue globale selon les règles existantes.
- Vérification attendue pour chaque ticket :
  - `npm run lint`
  - `npm run build`

# WEB-1 Rapports Terrain Web Réels

## Summary
- Remplacer le placeholder `/web/reports` par un vrai écran de rapports web.
- Le web doit permettre aux rôles autorisés de consulter, filtrer, ouvrir, valider/télécharger et exporter les rapports, sans logique terrain mobile.

## Key Changes
- Inspecter les routes et helpers existants :
  - `app/(web)/web/(dashboard)/reports/page.tsx`
  - `components/web-stub-page.tsx`
  - `lib/reports.ts`
  - `components/report-detail-page.tsx`
  - `app/api/reports/*`
  - `components/mobile-*-reports-page.tsx`
- Créer un composant web `ReportsWebPage`.
- Charger les rapports via les endpoints existants ou créer un endpoint web dédié si nécessaire.
- Rôles :
  - `SUPERVISOR` non ciblé web desktop;
  - `COORDINATOR` : rapports de son périmètre;
  - `GENERAL_SUPERVISOR` : rapports des sites confiés ou des sites dans son périmètre opérationnel;
  - `PROJECT_MANAGER` : rapports des projets dont il est chef;
  - `DIRECTION`/`ADMIN` : global.
- Ajouter filtres :
  - période;
  - projet;
  - chantier;
  - ressource;
  - statut rapport;
  - validation client.
- Ajouter actions :
  - ouvrir détail;
  - télécharger PDF/TXT selon l’existant;
  - exporter CSV/XLSX si disponible;
  - valider pour client pour les rôles autorisés.
- Ne pas exposer `storageKey` ni URL signée Supabase; les photos de rapport doivent passer par `/api/photos/[id]/content`.

## Test Plan
- `npm run lint`
- `npm run build`
- Tester `/web/reports` pour `COORDINATOR`, `GENERAL_SUPERVISOR`, `PROJECT_MANAGER`, `DIRECTION`, `ADMIN`.
- Vérifier qu’un rapport hors périmètre retourne `404` ou n’apparaît pas.

# WEB-2 Planning Web Pour Chefs De Projet Et Superviseurs Généraux

## Summary
- Ajouter une vraie page web de planning.
- Le web doit permettre de créer, modifier, supprimer, dupliquer et consulter les assignations, comme `/mobile/planning`, mais avec une interface desktop.

## Key Changes
- Ajouter `/web/planning`.
- Réutiliser la logique de `lib/mobile-planning.ts` ou extraire un helper commun `lib/planning.ts`.
- Rôles :
  - `PROJECT_MANAGER` : sites actifs de ses projets;
  - `GENERAL_SUPERVISOR` : sites explicitement confiés via `GeneralSupervisorSiteScope`;

- Garder les ressources assignables globales :
  - `SUPERVISOR`, `COORDINATOR`, `GENERAL_SUPERVISOR` actifs.
- Ne jamais bloquer une ressource parce qu’elle est déjà assignée ailleurs le même jour.
- Bloquer uniquement :
  - même ressource + même date + même site actif.
- UI desktop attendue :
  - vue journée/semaine;
  - filtres projet/chantier/ressource;
  - tableau ou grille par chantier;
  - drawer/modal de création/édition;
  - indication de disponibilité : “Disponible” ou “Assigné sur <chantier>”.
- Ajouter l’entrée navigation web “Planning” pour `PROJECT_MANAGER` et `GENERAL_SUPERVISOR`.

## Test Plan
- `npm run lint`
- `npm run build`
- Tester création d’assignation sur deux chantiers différents le même jour pour la même ressource.
- Tester qu’un GS ne voit que les sites confiés.
